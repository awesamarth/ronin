# Known Gaps

Ronin's current build is real, but it is still a local-first prototype.

## Deployment

The dashboard, database, GitHub webhook URL, Slack connector, Telegram connector, and Centaur execution backend still need a production deployment plan.

The local demo runs with:

- Dashboard on `localhost:3004`
- Docs on `localhost:3005/docs`
- Slack Socket Mode connector
- Telegram long-polling connector
- Centaur execution backend

## Tenant model

The current dashboard assumes a local operator surface and mostly uses the first configured org. A production version needs real auth, org switching, install ownership, and cleaner customer onboarding.

## Background work

Webhook and support-message paths can process workspace runs now, but production should move long-running execution work to a queue and worker.

That keeps HTTP request lifecycles short and gives better retry, cancellation, and progress reporting.

## Execution policy profiles

The current path supports JS/Next repos via the execution agent.

Production Ronin should detect repo stacks and apply policy profiles for ecosystems such as Python, Rust, Go, and Java.

## Support routing UI

Slack and Telegram mappings are DB-backed and functional, but the UI is still operator-oriented.

A customer-ready flow should guide users through selecting a workspace, channel, repo, and allowed actions without exposing too much internal vocabulary.
